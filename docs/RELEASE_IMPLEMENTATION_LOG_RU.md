## 4. Мобильная форма и сохранность черновиков

Реализовано 2026-10-29:

- Вместо десяти постоянно видимых кнопок шагов — текущий шаг и раскрываемая навигация. После перехода фокус попадает на заголовок нового шага.
- Дополнительные сведения о подъезде раскрываются по запросу. В короткой перевозке адреса и сведения о доступе больше не повторяются в обоих шагах.
- Добавлены доступные состояния выбранных вариантов, семантика progressbar и подсказки автозаполнения адреса.
- Анонимный пользователь может явно включить сохранение текстового черновика в текущей вкладке (sessionStorage, до 24 часов после последнего обновления). До выбора ничего не сохраняется в браузерное хранилище.
- Перед включением объясняется, что сохраняются адреса и заметки, и что это не рекомендуется на общем компьютере. Файлы, имена файлов, OTP, данные авторизации и серверные идентификаторы не сохраняются.
- При восстановлении проверяются версия, срок, размер и структура. Повреждённые данные отбрасываются; недоступное хранилище показывает предупреждение вместо ложного сообщения об успехе.
- Снятие выбора, вход, выход, успешная публикация и начало новой заявки очищают локальную копию. При выходе также очищаются поля текущей формы.
- Добавлено предупреждение браузера перед уходом с несохранёнными изменениями; доступность такого диалога зависит от браузера, особенно на телефонах.
- Во время запросов сохранения поля и переходы блокируются, чтобы ответ сервера не затёр параллельные изменения.
- Перед публикацией обязательно сохраняются последние значения, даже если пользователь перешёл к публикации напрямую через навигацию.
- Убрана неработающая имитация выбора фотографий: отображается честное сообщение о недоступности загрузки.

Проверка:

- Web: 26/26 тестов; в том числе восстановление после повторного открытия компонента, выключение сохранения, срок жизни, повреждённая структура, исключение секретов/файлов, отказ хранилища и порядок save → publish.
- API: 66/66 без PostgreSQL integration. Статическая проверка хранения ограничивает sessionStorage единственным адаптером анонимных черновиков; в остальном production-коде browser storage запрещён.
- Общий lint, TypeScript и Next production build: успешно.
- Браузер: 320/390px без горизонтального переполнения, переход с фокусом на новый заголовок, восстановление введённого города и текущего шага после reload.

Осталось: свести процесс к шести смысловым группам, завершить полевую валидацию и серверные согласия, подключить настоящие загрузки и production auth. Текущая компактная навигация не означает, что полная переработка формы завершена.

## 6. Серверное подтверждение возраста, условий и передачи контактов

Реализовано 2026-10-29:

- В API новой регистрации без этих подтверждений не создаются аккаунт и сессия. Версии проверяет сервер, время берётся на сервере. Повторный вход не переписывает предыдущую запись.
- Существующий аккаунт с устаревшим подтверждением получает необходимость повторного принятия; публикация без актуальной записи запрещена и при прямом вызове API.

- Добавлены таблицы истории и миграция. Реляционная регистрация и запись согласия сохраняются транзакционно; публикация и разрешение на передачу сохраняются совместно.

## 7. Устранение уязвимой зависимости сборки API

Реализовано 2026-10-29:

- `dotnet nuget why` подтвердил цепочку: EF Design 10.0.0 → MSBuild/Roslyn → System.Security.Cryptography.Pkcs 9.0.0.
- Добавлена private-привязка System.Security.Cryptography.Pkcs 9.0.21. Это минимальный исправленный patch той же ветки, без необязательного обновления всего EF/Npgsql. Все ветки графа теперь разрешаются в 9.0.21.
- `Directory.Build.props` включает аудит прямых и транзитивных NuGet-зависимостей для API и тестов. NU1901–NU1904 становятся ошибками восстановления/сборки; предупреждения не подавляются.
- Основания: официальные [CVE-2026-84008](https://github.com/dotnet/announcements/issues/468) и [CVE-2026-70162](https://github.com/dotnet/announcements/issues/454). Обе рекомендации указывают 9.0.21 как исправленную версию ветки 9.

Проверка:

- Restore после изменения, 79/79 API-тестов без PostgreSQL integration: успешно, без NU1902/NU1903.
- `dotnet list ... package --vulnerable --include-transitive --no-restore`: известных уязвимых пакетов API по текущим источникам NuGet не найдено.
- EF migration model check: изменений относительно последней миграции нет.
- Release publish: успешно; артефакт создаётся локально в игнорируемой `.tools/release-checks/api-20261029`, не развёрнут на сервере.

Граница проверки: NuGet-аудит не подтверждает безопасность всего приложения или операционной системы. На этой машине установлен runtime 10.0.4; окружение релиза необходимо отдельно подготовить на исправленном .NET 10.0.13 или новее, пересобрать/проверить и развернуть там приложение. Системные runtime пользователя в этом этапе не изменялись.

## 18. Причины невидимости заявки и подтверждение текущей версии

Сервер использует один SQL-критерий с каталогом, включая местную дату Израиля, телефон, политики, состояние и содержимое текущей версии. «Активна» больше не подразумевает автоматически «видна в каталоге». SoldOut и неизвестный канонический город сохраняют прежнюю семантику каталога.
- Если не хватает только разрешения на передачу контактов, владелец может явно подтвердить текущую версию без повторного ввода заявки. ## 19. Редактирование опубликованной заявки с проверкой изменений

Отсутствие содержательных изменений не создаёт новую версию.
- Перед сохранением требуется новое явное согласие с фактическим пределом получателей и известной версией текста; флажок изначально снят. Любое изменение формы сбрасывает согласие. Смена типа требует отдельного подтверждения замены прежней категории содержимого/услуг; возврат к прежнему типу до записи сохраняет введённые поля. Цена, история покупателей, SoldOut и жизненный цикл не сбрасываются; уведомления перевозчиков и отзыв уже полученных ими копий не обещаются.
- Перед единственным PUT повторно проверяются аккаунт, владелец и текущая версия. Поля и навигация блокируются на время проверки/сохранения. При конфликте или неясном результате локальные изменения остаются в памяти, повторная запись блокируется до чтения сервера и явного выбора: загрузить серверную версию либо продолжить проверку своих данных. Последний вариант означает полную замену содержимого, а не автоматическое объединение чужих изменений.
- Возвращение во вкладку/BFcache скрывает приватный интерфейс до проверки доступа. Смена аккаунта или потеря прав очищает данные; запоздалый ответ старой операции их не восстанавливает. Чтения ограничены 10 секундами, запись вместе с CSRF — 20 секундами; автоматических повторов записи нет. Локальное хранилище браузера для опубликованных правок не используется, перед уходом с несохранёнными изменениями запрашивается стандартное предупреждение браузера.
- Дата формы теперь использует календарь Израиля, включая летнее время, и совпадает с серверной проверкой около полуночи. Серверные HTTP-регрессии выявили 14 ошибок валидации: неизвестные enum и управляющие символы раньше могли приниматься, вложенные null приводили к 500. Теперь они дают контролируемый 400 до записи; допустимые переносы строк и табуляция сохранены. Общая валидация защищает также обычные черновики. Добавлена PostgreSQL-гонка изменения владельца во время PUT.
- Независимая проверка обнаружила ошибочную маршрутизацию первой кнопки на удалённый шаг публикации; исправлены индексы и обработчик, добавлен сценарий обычного пошагового прохождения без записей. Справка описывает новый порядок редактирования и восстановление после конфликта. Юридические тексты и версия согласий не изменялись.

Проверки: **420/420 web-тестов**, **447/447 API-тестов без PostgreSQL**, общий ESLint, TypeScript и production Next.js build прошли. Среди новых сценариев — 35 интеграционных проверок редактора/API-клиента, 15 проверок сохранности модели и 40 серверных HTTP-регрессий. PostgreSQL-гонка владельца скомпилирована, но локально не запускалась: test DB не настроена; её выполняет обязательный CI. HTTP smoke подтвердил 200/noindex/начальный экран проверки доступа для нового редактора, а также 200 и новый раздел редактирования на странице справки. Локальный сервер остановлен.
