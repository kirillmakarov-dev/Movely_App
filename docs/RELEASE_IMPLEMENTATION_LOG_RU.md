## 2. Визуальная основа главной и мобильная навигация

Реализовано 2026-10-29:

- Сгенерирована иллюстрация переезда; есть видимая подпись о происхождении изображения.
- Главная перестроена вокруг двух сценариев: переезд квартиры и перевозка отдельных вещей.
- Добавлены понятные этапы и раскрывающиеся ответы. Убраны вымышленные «свежие заявки».
- Статус ознакомительной версии указан явно, без обещаний работающих платежей и подбора перевозчиков.
- Подключён шрифт с реальными Hebrew-глифами. Приведены к единому стилю цвета, карточки и кнопки.
- Мобильное меню: крупная кнопка, aria-expanded, закрытие Escape с возвратом фокуса, ссылка пропуска навигации.
- Неработающий переключатель языков скрыт до полноценного исправления локализации. Поддерживаемый интерфейс этого этапа — иврит.
- Правила дизайна синхронизированы с кодом, происхождение изображения записано в VISUAL_ASSETS.md.

Проверка:

- Production Next build: успешно, включая TypeScript и генерацию маршрутов. Sites/Vinext build также успешно прошёл все пять стадий.
- Главная: просмотр в браузере на desktop, 390px и 320px; ширина документа не превышает viewport.
- Проверены открытие меню, Escape, возврат фокуса, раскрытие FAQ, переход к созданию заявки.
- ESLint изменённых TSX-файлов: успешно. Общий lint пока НЕ проходит: захватывает dist и выявляет существующие ошибки в форме/локализации. Это отдельный следующий шаг, не скрытая успешная проверка.
- Предыдущий базовый прогон тестов: web 15 failures из-за устаревших английских ожиданий; API 65 passed / 1 failed (проверка localStorage), PostgreSQL integration исключены. Этот этап не заявляет исправление этих тестов.

Осталось по визуалу: форма (на мобильном десять пунктов шагов занимают слишком много места), остальные публичные страницы и кабинеты, 200% zoom, screen reader, реальные телефоны.

## Дальнейшая последовательность

1. Исправить проверки качества и завершить честную Hebrew-first локализацию.
2. Переработать мобильную форму, прогресс, ошибки и сохранение черновика.
3. Реализовать согласия 18+, версионирование условий и явное объяснение передачи контактов на сервере и в интерфейсе.
4. Добавить содержательные privacy/terms/help/accessibility страницы. Реальные сведения оператора и юридическая проверка остаются обязательным условием публичного релиза.
5. Закрыть серверные и инфраструктурные блокеры из плана: production auth/SMS, CORS, secrets, rate limits, health, наблюдаемость и резервное восстановление.
6. Довести коммерческие сценарии и реальные данные вместо демонстрационных экранов; провести интеграционные, мобильные и пользовательские проверки.

Полный релиз пока не готов. Каждый дальнейший шаг должен сопровождаться отдельными проверками и записью результата.
